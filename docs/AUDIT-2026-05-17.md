# QuizWorld Code Audit — 2026-05-17

Audited against all major user flows. Live production: https://www.quizworld.xyz

## Summary

| Severity | Count |
|---|---|
| 🔴 High | 4 |
| 🟡 Medium | 6 |
| 🟢 Low | 5 |

---

## Flow 1: Auth (Sign up / Sign in / Google SSO / Sign out)

- [HIGH] `profiles.is_admin` is queried in `app/admin/page.tsx` but there's no middleware or server-side auth guard on `/admin` — anyone who knows the URL can attempt to load the page; the check is client-side only (useEffect). A logged-out user briefly sees a flash before redirect.
- [MEDIUM] No auth guard on `/report/[pin]` — unauthenticated users can access game result reports for any PIN directly.
- [LOW] Google SSO was fixed (2026-05-15) but no automated test covers the OAuth callback path. If the Supabase OAuth client secret rotates, it'll silently break again.

---

## Flow 2: Quiz Creation (manual, paste, AI topic/URL/document)

- [HIGH] In-memory rate limiter in `lib/rate-limit.ts` resets on every Vercel cold start/function instance restart. On Vercel's serverless model, each function invocation may get a fresh Map — meaning rate limits are **effectively not enforced** in production. Comment in the file even says "use Redis-backed rate limiting for production". AI endpoints (`/api/ai-source-draft`, `/api/import-url`, `/api/ai-enrich`) are unprotected against abuse.
- [MEDIUM] `app/create/page.tsx` loads an existing draft via `.select("*, questions(*, answers(*))")` but no RLS policy explicitly covers `quiz_drafts` reads by draft owner. If RLS is enabled on `quiz_drafts` with wrong policy, edit-draft flow returns empty data silently.
- [MEDIUM] AI generation uses `response_format: { type: "json_object" }` — this is an OpenAI-specific param. Since `QUIZWORLD_AI_API_URL` defaults to Groq, and Groq supports this, it works — but if the URL is ever changed to a non-OpenAI-compatible provider this will silently fail or return malformed JSON.
- [LOW] File import supports `.pdf` and `.docx` but there's no file size validation on the client before upload; server only caps fetch size for URL imports.

---

## Flow 3: Dashboard (list, edit, delete, publish/unpublish, archive)

- [MEDIUM] Dashboard fetches quizzes, drafts, versions, game sessions, and profile all in parallel (5 concurrent Supabase queries). If any one fails, the entire `setError` path fires and the dashboard shows nothing. No partial-load fallback — one bad query nukes the whole page.
- [LOW] `archived_at` soft-delete works, but there's no hard-delete option in the UI. Archived quizzes accumulate in DB permanently.
- [LOW] Restore-from-version (`dashboard/page.tsx:229`) sets `is_public: version.snapshot.is_public ?? version.is_public` — if the snapshot was taken when the quiz was public and is now private, restoring it will unexpectedly re-publish the quiz.

---

## Flow 4: Study Mode

- [MEDIUM] `study_progress` upsert in `app/study/[id]/page.tsx:106` uses `onConflict: "user_id, quiz_id"` — this requires a unique constraint on `(user_id, quiz_id)` in Supabase. If that constraint doesn't exist in the live DB, the upsert silently inserts duplicates instead of updating progress. Study stats will then show wrong totals.
- [LOW] Study page shows average mastery across all quizzes — but `mastery` is nullable; `?? 0` defaults are applied inconsistently across components, so a user with no progress shows 0% rather than "No data yet".

---

## Flow 5: Host a Game

- [HIGH] `NEXT_PUBLIC_GAME_SERVICE_URL` is **not set in Vercel production env** (not in `vercel.json`, not in `.env.local`). The config falls back to `gameServiceUrl = ""`, making `isPhoenixGameEngine = false` and `liveGameEngineMisconfigured = true`. The `/host` page will show a "Phoenix misconfigured" error banner. **Live game hosting is broken in production** unless this env var is set in the Vercel dashboard.
- [MEDIUM] Phoenix `finish_game_and_record_results` RPC requires `auth.uid() = host_id` — but the host token passed to Phoenix is a separate JWT, not a Supabase user JWT. If the RPC is called from the server with the wrong auth context, it'll throw "Only the host can finish the game" even for a valid host.

---

## Flow 6: Join a Game / Player Flow

- [HIGH] Same root cause as Flow 5 — `NEXT_PUBLIC_GAME_SERVICE_URL` missing means `/join` page shows "Phoenix is selected as the live engine, but `NEXT_PUBLIC_GAME_SERVICE_URL` is missing." **Players cannot join any live game in production.**

---

## Flow 7: Explore

- [LOW] `app/explore/page.tsx` fetches all public quizzes (no pagination, no limit). As the DB grows this will slow down significantly and eventually hit Supabase response size limits.
- [LOW] Creator profile lookup (`.select("id, username, display_name, avatar")`) — `avatar` column may not be populated for all users; no fallback avatar shown in the UI if null.

---

## Flow 8: Present Mode

- No blocking bugs found. Auth guard exists. `access_token` is checked before socket connection. Slides load correctly.
- [LOW] Present mode has no offline/reconnect handling — if the presenter loses connection mid-session, the audience screen freezes with no indication.

---

2. 🔴 **Replace in-memory rate limiter with Upstash Redis** or add auth-only guard on AI endpoints.
3. 🔴 **Add server-side auth guard on `/admin`** route (middleware or server component check).
4. 🟡 **Add unique constraint `(user_id, quiz_id)` on `study_progress`** if not already in DB.
